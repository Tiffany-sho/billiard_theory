# データ契約：座標系・弧長・法線の定義

作成日: 2026-08-25

**この文書が正。** 弧長 s の原点と向き、法線 n の向き、sinφ の符号、パラメータ名の綴りは、要件定義書ではなくここに書く。実装（Python / JavaScript）とこの文書が食い違ったら、まずここを直してから実装を直す。

以下は Python（`class/`, `func/squre/`）と JavaScript（`simulation.html`）の**両方が守っている規約**。決定に至った経緯と理由は `docs/requirements.md` §7（決定事項 D1–D10）にある。

食い違いは `node tools/check_html.js` が検出する（5形状の既定ケースで `x, y, s または θ, sinφ` を突き合わせ、差が 1e-6 以上なら落ちる）。規約そのものの破れは `python tests/test_invariants.py` が検出する。

⚠️ は「まだ直っていない／注意が要る」箇所にだけ付けてある。

## 1. 共通の定義

### パラメータ名（この綴りで統一する）

| 記号 | 意味 | 使う形状 |
|---|---|---|
| `W` | 矩形部の幅 | 矩形・楕円・スタジアム・シナイ |
| `H` | 高さ。スタジアムでは半円の直径 | 全形状 |
| `D` | 中央の円形障害物の直径 | シナイのみ |
| `W_r` | 右半分の幅 | 卵型のみ |
| `W_l` | 左半分の幅 | 卵型のみ |
| `bound_num` | 衝突回数 N | 全形状 |
| `s` | 弧長座標（ポアンカレ断面の横軸） | 矩形・スタジアム・シナイ |
| `theta` | 角度座標（ポアンカレ断面の横軸） | 楕円・卵型 |

W と H は **直径・全幅** であって半径・半幅ではない。境界の式ではつねに `W/2`, `H/2`, `D/2` として現れる。

### sinφ の定義

```
v̂ = v / |v|
n̂ = n / |n|
sinφ = v̂ × n̂ = v̂x · n̂y − v̂y · n̂x       （2次元の外積）
```

n の向き（内向き／外向き）が形状ごとに違うため、**sinφ の符号は形状によって意味が揃っていない**。§2 の各形状の欄を参照。

### ポアンカレ点の作られ方

`Stadium` / `Sinai` / `Egg` のコンストラクタは次を作る。

```
positions  = [初期位置, 衝突1, 衝突2, ..., 衝突N]      長さ N+1
velocities = [初速度,   反射1, 反射2, ..., 反射N]      長さ N+1
```

**断面に載せるのは衝突点 1..N だけ**（`positions[1]` 〜 `positions[N]`）。初期位置は境界上にないので載せない。

- Python: `poincare()` は `range(1, self.bound_num + 1)`。`tests/test_invariants.py` の `test_index_range_is_collisions_only()` がこれを固定している
- JS: `simulate()` が衝突点だけを返すので、そもそも初期位置は混ざらない

⚠️ **`create_occupany_area()` にはまだ `range(self.bound_num)` が残っている**（初期位置を1個数えて N 回目を捨てる）。S2・S3 に着手するときに直す。TODO コメントあり。

**sinφ に使う速度**: JS は「その衝突に**入ってきた**速度」（反射前）を使う。Python の `poincare()` は `velocities[i]`（反射**後**）を使う。数学的には同値で
（`v_out × n̂ = (v_in − 2(v_in·n̂)n̂) × n̂ = v_in × n̂`）、実測でも差は 1.665e-16 に収まる。
`tools/dump_section.py` は JS 側に合わせて入射速度で書き出すので、CSV の `vx_in / vy_in` は `velocities[i]` とは別物。

### 速度の扱い

`find_reflect_direction` は反射後に `reflected / |reflected| * speed` と元の速さで再スケールする。衝突列は速度の**向き**だけで決まるため、速さは軌道に数学的な影響を与えない。

⚠️ **ただし数値的には影響する。** 速さを変えると交点計算に入る値が変わって丸めがずれ、カオス系では増幅する。実測（スタジアム W=H=5、向きは同じで速さだけ変更）:

| 速さ | 最初に差が出る衝突 | その時の差 | 20 衝突での差 | 500 衝突での差 |
|---|---|---|---|---|
| 1e-4 | 2 | 8.88e-16 | 1.32e-8 | 約 10（別軌道） |
| 1 | 3 | 2.22e-16 | 3.27e-9 | 約 10（別軌道） |
| 100 | 2 | 8.88e-16 | 5.20e-8 | 約 10（別軌道） |

このため、軌道図でのドラッグは**向きだけを変えて速さは保つ**（決定 D14）。速さを触ると、向きを変えたつもりがないのに軌道が作り直される。

### 浮動小数の比較

境界の判定は形状ごとにばらばら。移植時にそのまま持ち込むと JS で分岐が変わる。

| 箇所 | 比較 |
|---|---|
| `stadium_func.get_normal_vector` | `abs(p[1]) == H/2` — 厳密比較 |
| `sinai_func.get_n_vector_arc_length` | 外壁は `p[1] == H/2` など厳密比較、円のみ `abs(|p| − D/2) < 1e-10` |
| `sinai_func.find_reflect_direction` | 円は `< 1e-10`、外壁は厳密比較 |
| `squre.get_normal_vector` | 厳密比較 |

**JS 側もこの比較をそのまま写している。独自に境界へ丸めない（スナップしない）。**

当初は「JS 側で交点を境界へ丸めれば厳密比較が安全に効く」と考えたが、それをやると座標が Python と 1e-16 ずれる。スタジアム・シナイはカオス系なので 35 衝突のあいだに増幅されえて、受け入れ基準13（1e-6 一致）を満たすための施策が逆に基準を壊しうる。実際、そのまま写した結果は **矩形・スタジアム・シナイで位置・速度がビット単位で一致**した（楕円・卵型は `Math.atan2` と `np.arctan2` の 1 ULP 差で座標のみ 4.44e-16）。

厳密比較が成立するのは、直線部の交点が `y` に `±H/2` を直接代入して作られるため。円弧部の交点は算術で出るのでそこに乗ることはない。唯一スナップするのはシナイの障害物（`hit *= (D/2)/|hit|`）で、これは Python 側が元からやっている。

⚠️ それでも丸め誤差で分岐から落ちることはありうる。JS は Python が `None` / `inf` を返す経路で `null` を返し、**計算を止めて「何回目で止まったか」を画面に出す**。黙って NaN を先へ流さない。

## 2. 形状ごとの定義

### 2-1. スタジアム（`class/stadium_func.py`）

境界は 上下辺 `y = ±H/2, |x| ≤ W/2` と、中心 `(±W/2, 0)`・半径 `H/2` の半円2つ。`W = 0` で半径 `H/2` の真円になる。

**弧長 s**（`get_arc_length`）— 原点は上辺の中央、上辺を右向きが正:

| 条件 | s |
|---|---|
| `\|x\| ≤ W/2` かつ `y > 0` | `x` |
| `\|x\| ≤ W/2` かつ `y ≤ 0`、`x > 0` | `W + Hπ/2 − x` |
| `\|x\| ≤ W/2` かつ `y ≤ 0`、`x ≤ 0` | `−W − Hπ/2 − x` |
| `\|x\| > W/2`、`x > 0` | `W/2 + (H/2)·acos(2y/H)` |
| `\|x\| > W/2`、`x < 0` | `−W/2 − (H/2)·acos(2y/H)` |

- 範囲: `s ∈ [−(W + Hπ/2), W + Hπ/2]`、全長 `2(W + Hπ/2)`
- 分岐は **x で先に判定してから y で分ける**（y の符号で先に分けるのではない）
- 破線（直線部と円弧部の境界）: `s = ±W/2` と `s = ±(W/2 + Hπ/2)` の4本

**法線 n**（`get_normal_vector`）:

| 条件 | n | 向き |
|---|---|---|
| `abs(y) == H/2` | `(0, −sign(y))` | 領域の**内**向き |
| それ以外（円弧部） | `(center − p) / \|center − p\|`、`center = (sign(x)·W/2, 0)` | 領域の**内**向き |

どちらも正規化済みの単位ベクトルを返す（この形状だけ。他は正規化していない）。

以前は円弧部が `p − center`（外向き）で、直線部と向きが逆だった。反射は n の符号に不変なので軌道は正しかったが、断面の sinφ が接続点 `s = ±W/2` で符号反転していた（2026-08-25 に修正。決定 D1）。

⚠️ 円弧部の `center` は `if intersection[0] > W/2` の else で `(−W/2, 0)` を取る。`|x| ≤ W/2` の点がここへ来ることはない（上の分岐で弾かれる）が、許容誤差を導入すると来うる。

### 2-2. シナイ（`class/sinai_func.py`）

境界は 外壁 `|x| ≤ W/2, |y| ≤ H/2` の矩形と、原点中心・直径 `D` の円形障害物。

**弧長 s と 法線 n**（`get_n_vector_arc_length`）— 原点は外壁の右上角、外壁を**時計回り**にたどる:

| 区間 | 条件 | s | n | 向き |
|---|---|---|---|---|
| 上辺 | `y == H/2` | `W/2 − x` | `(0, −1)` | 内向き |
| 左辺 | `x == −W/2` | `W + H/2 − y` | `(1, 0)` | 内向き |
| 下辺 | `y == −H/2` | `W + H + W/2 + x` | `(0, 1)` | 内向き |
| 右辺 | 上記以外（`x == W/2`） | `2W + H + H/2 + y` | `(−1, 0)` | 内向き |
| 障害物 | `abs(\|p\| − D/2) < 1e-10` | `(D/2)·atan2(y, x) + πD/2 + 2(W + H)` | `(x, y)` | 内向き（中心から外＝領域側） |

- 外壁の区間: `s ∈ [0, 2(W + H)]`
- 障害物の区間: `s ∈ (2(W + H), 2(W + H) + πD]`
- 範囲: `s ∈ [0, 2(W + H + πD/2)]`、全長 `2(W + H + πD/2)`
- 破線: `s = 2(W + H)` の1本のみ（外壁と障害物の切れ目）
- **n はスタジアムと違い全区間で領域内向きに揃っている**。sinφ の符号は形状内で一貫する

**判定の順序に依存**: 障害物の判定が最初に来る。外壁は `if / elif` の連鎖で、右辺だけが `else`（明示的な `x == W/2` の判定ではない）。

**角での反射**（`find_reflect_direction`）: `abs(x) == W/2 かつ abs(y) == H/2` のとき `(−vx, −vy)` を返す。来た方向へ真っ直ぐ戻る。

**領域内の判定**（受け入れ基準8）: 外壁の内側 **かつ** 障害物の外側、すなわち `|x| < W/2 かつ |y| < H/2 かつ |p| > D/2`。

### 2-3. 矩形（`func/squre/`）

**弧長 s**（`get_arc_length`）— スタジアムと同じ中央原点方式で、円弧を直線に置き換えたもの:

| 条件 | s |
|---|---|
| `abs(y) == H/2` かつ `y > 0` | `x` |
| `abs(y) == H/2` かつ `y < 0`、`x > 0` | `W + H − x` |
| `abs(y) == H/2` かつ `y < 0`、`x ≤ 0` | `−W − H − x` |
| それ以外、`x > 0` | `W/2 + H/2 − y` |
| それ以外、`x < 0` | `−W/2 − H/2 + y` |

- 範囲: `s ∈ [−(W + H), W + H]`、全長 `2(W + H)`
- 破線: `s = ±W/2` と `s = ±(W/2 + H)` の4本
- ⚠️ スタジアムは x で先に分岐、矩形は **y で先に分岐**。同じ「中央原点」でも分岐の順序が違う

**法線 n**（`get_normal_vector`）— ⚠️ この関数だけ **速度 v を引数に取る**（`get_normal_vector(intersection, v, W, H)`）:

| 条件 | n |
|---|---|
| 角（`abs(x) == W/2` かつ `abs(y) == H/2`） | `−v / \|v\|` → sinφ = 0 |
| 左右辺（`abs(x) == W/2`） | `(−sign(x), 0)` 内向き |
| 上下辺 | `(0, −sign(y))` 内向き |

**角に来たら来た道を戻る**（`v → −v`）。矩形・シナイとも同じ（決定 D5）。

以前は矩形の `find_reflect_direction` が `np.array([0, 0])` を返し、直後の `reflected / np.linalg.norm(reflected)` が 0÷0 になって速度が NaN になり、以降の軌道が黙って壊れていた（2026-08-25 に修正）。

⚠️ `get_normal_vector`（矩形）は角で `−v̂` を返すので、その1点だけ `sinφ = 0` になる。角は measure-zero なので通常は出会わないが、`v0` の傾きが有理数だと周期軌道になって規則的に角を突くことがある（`tools/dump_section.py` の矩形ケースが実際にこれを踏んだので、`v0` を無理数傾きにしてある）。

### 2-4. 楕円（卵型カーネルに `W_r = W_l = W` を渡したもの）

境界は `(x/(W/2))² + (y/(H/2))² = 1`。

**楕円は独立した実装を持たない。** 卵型（2-5）に `W_r = W_l = W` を渡したものと厳密に同じで、実測でも 200 衝突にわたって差 0 だった。`func/ellipse/` の Newton 法版は使っていない（未決事項1）。

- ポアンカレ横軸は **弧長ではなく角度** `theta = atan2(y, x) ∈ (−π, π]`
- 法線: 卵型と同じ `−((H/2)²·x, (W/2)²·y)` — 勾配の符号を反転した領域の**内**向き
- 範囲: `theta ∈ [−π, π]`、`sinφ ∈ [−1, 1]`
- 破線: `theta = ±π/2` の2本
- ⚠️ この `theta` は**弧長に比例しない**。断面上の点の密度は幾何的な密度と一致しないため、スタジアム・シナイの断面と直接は比較できない

### 2-5. 卵型（`class/egg.py`, `class/egg_func.py`）

境界は右半分 `(x/(W_r/2))² + (y/(H/2))² = 1, x ≥ 0`、左半分 `(x/(W_l/2))² + (y/(H/2))² = 1, x ≤ 0` を貼り合わせたもの。`W_r == W_l` で楕円と一致する。

- ポアンカレ横軸は角度 `theta = atan2(y, x) ∈ (−π, π]`
- 法線（`class/egg_func.py: get_normal_vector`）:

| 条件 | n | 向き |
|---|---|---|
| `x > 0` | `−((H/2)²·x, (W_r/2)²·y)` | 領域の**内**向き |
| `x ≤ 0` | `−((H/2)²·x, (W_l/2)²·y)` | 領域の**内**向き |

正規化していない（呼び出し側で割る）。

`x == 0`（上下の頂点）の場合分けは要らない。x 成分が 0 になるので `W_r` / `W_l` のどちらを使っても向きは `(0, −sign(y))` になる。以前あった `(0, sign(vy))` は**速度に依存**していて、他の点と意味が揃っていなかった（2026-08-25 に解消。決定 D1）。

- 範囲: `theta ∈ [−π, π]`、破線 `theta = ±π/2`（左右の楕円の貼り合わせ位置）
- ⚠️ `x = 0` で曲率が不連続に変わる（`W_r ≠ W_l` のとき）。この不連続がカオス性の源であり、断面の破線はその位置を示している

## 3. 描画の契約

| 項目 | 契約 |
|---|---|
| 軌道図のアスペクト比 | つねに 1:1。パネルが正方形でない場合、余りは左右または上下の余白にする |
| ポアンカレ断面のアスペクト比 | 固定しない。横軸を枠幅いっぱいに引き伸ばし、縦軸 `sinφ ∈ [−1, 1]` は固定高さ |
| 破線の色 | 赤（既存の matplotlib 版 `setting.py` に合わせる）。`linestyle="--"` 相当 |
| 断面の点の大きさ | matplotlib 版は `s=0.05`。JS は 1.2px の矩形（`fillRect`）。密な点群を潰さない最小サイズにする |
| 軌道の線の濃さ | 3000 本以下なら線分を1本ずつ描いて重なりを濃くする（matplotlib の `alpha=0.1` と同じ効果で、軌道の密度が見える）。それ以上は1本のパスにまとめて速度を優先する |
| 色の持ち方 | JS 側は CSS カスタムプロパティ（`--boundary` / `--orbit` / `--dash` / `--dot`）から `getComputedStyle` で読む。**描画コードに生の色コードを書かない** |
| canvas の寸法 | `clientWidth` / `clientHeight`（内容ボックス）を使う。`getBoundingClientRect()` は `box-sizing:border-box` の 1px ボーダーを含むため、それを `canvas.width` にすると描画面が縮小表示され、マウス座標と数 px ずれてホバーが隣の点を拾う |
| 重ね描きの色 | `setting.py: basic_colors` の 100 色を順に使う |
| 占有領域の分割数 | `divide`。既定 50。⚠️ Python 版は引数を受け取りながら内部で 50 をハードコードしている（要件定義書の未決事項2） |
| 断面のヒットテスト | データ座標 `(s, sinφ)` を 128×32 の格子に振り分けた索引で最近傍を引く。画面座標ではなくデータ座標で持つのでリサイズしても作り直さない。20000 点で 1 回 0.017 ms（全走査 0.729 ms の 44 倍速） |

## 3-2. 重ね描き・占有領域・エントロピーの契約

| 項目 | 契約 |
|---|---|
| 境界パラメータ t | 弧長軸（矩形・スタジアム・シナイ）は弧長 s そのもので `coord()` の逆関数。角度軸（楕円・卵型）は媒介変数の角度で、`x = a cos t, y = (H/2) sin t` の t。⚠️ 後者は断面の横軸（極角 `atan2(y,x)`）とは `a ≠ H/2` のとき一致しない |
| 初期値の撒き方 | 境界を epoch 等分し、i 番目の区画の中から一様に1点選ぶ。そこから内向き法線を基準に `phi ∈ (-π/2, π/2)` の一様乱数で撃ち出す。速さは `1/100`（Python の `*_create_setting` と同じ） |
| 乱数 | mulberry32（決定的）。seed を変えると撒き直す。⚠️ Python の `np.random` とは別物なので **Python の poincare_mix の図とは一致しない** |
| 色 | `BASIC_COLORS[i % 100]`。`setting.py: basic_colors` が正で、`tools/dump_section.py` が HTML へ差し込む |
| ヒストグラムのビン | 範囲 `[lo, hi]` を divide 等分、`sinφ` は `[-1, 1]` を divide 等分。添字は `cells[iy * divide + ix]` で `iy = 0` が `sinφ = -1` 側。Python の式とは書き方が違うが、同じデータで S と使用セル数が完全一致することを確認済み |
| エントロピー | `S = -Σ p log2 p`（p = セル数 / 総点数）。`class/(形状).py の shannon_entropy_value` と同じ |
| 理論上限 | `log2(divide^2) = 2 log2(divide)`。一様分布のときの値 |

**妥当性の実測**（divide = 50、上限 11.288、衝突 20000）:

| 形状 | S | 使用セル |
|---|---|---|
| 円（W = 0・積分可能） | 5.644 | **50** / 2500 |
| 楕円（積分可能） | 6.367 | 92 / 2500 |
| 矩形（積分可能） | 6.690 | 108 / 2500 |
| 卵型 | 11.135 | 2492 / 2500 |
| スタジアム（エルゴード） | 11.192 | 2498 / 2500 |
| シナイ（エルゴード） | 11.197 | 2496 / 2500 |

円がちょうど 50 セル・`S = log2(50) = 5.6439` になるのは、断面が `sinφ` 一定の水平線1本に乗り、格子の1行だけが埋まるため。積分可能系とエルゴード系がはっきり分かれている。

## 4. 既定値

### 起動時（`simulation.html`）

| 項目 | 値 | 出典 |
|---|---|---|
| 形状 | スタジアム | — |
| `W`, `H` | 5.0, 5.0 | `main/stadium/poincare.py` |
| 初期位置 | `(0.5, 0.0)` | `main/stadium/poincare.py` |
| 初速度 | `(0.02/√29, 0.05/√29)` ≒ `(0.0037139067635410376, 0.009284766908852594)` | `main/stadium/poincare.py` |
| 衝突回数 | 2000 | 差し戻し R8 で決定 |
| 衝突回数の上限 | 20000 | 決定 D10（20000 衝突の計算は実測 47 ms） |
| 表示モード | 一括表示 | アニメーション既定だと起動時に何も出ず、受け入れ基準5 を満たせない |

### 形状ごとの既定パラメータ（`SHAPES[*].params[].def`）

| 形状 | パラメータ |
|---|---|
| 矩形 | `W = 5.0`, `H = 5.0` |
| 楕円 | `W = 6.0`, `H = 4.0` |
| スタジアム | `W = 5.0`, `H = 5.0` |
| シナイ | `W = 5.0`, `H = 5.0`, `D = 2.0` |
| 卵型 | `W_r = 6.0`, `W_l = 3.0`, `H = 4.0` |

形状を切り替えると、この既定値に入れ替わる。前の形状の値を持ち込むと、シナイで `W < D` のような成り立たない組み合わせになりうるため。

### 検算に使う参照ケース（`tools/dump_section.py`）

いずれも衝突 35 回。**角に当たる初期条件は使えない**（1 ULP のずれで角判定から壁判定へ転ぶため参照値として脆い）。ツールが検出して落とす。

| 形状 | 初期位置 | 初速度 | 備考 |
|---|---|---|---|
| スタジアム | `(0.5, 0.0)` | `(0.02, 0.05)/√29` | `main/stadium/poincare.py` と同じ |
| シナイ | `(1.3, 0.7)` | `(0.02, 0.05)/√29` | `(1.5, 0.0)` は1回目が角 `(2.5, 2.5)` だった |
| 矩形 | `(0.5, 0.0)` | `(1, √2)/√3` | 傾き 5/2 は 5×5 の正方形で周期軌道になり 6 衝突ごとに角を突く |
| 卵型 | `(0.3, 0.1)` | `(0.02, 0.05)/√29` | |
| 楕円 | `(0.3, 0.1)` | `(0.02, 0.05)/√29` | 卵型カーネルに `W_r = W_l = 6.0` |
