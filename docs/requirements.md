# 要件定義：ビリヤード軌道・ポアンカレ断面 シミュレーション HTML

作成日: 2026-08-25
最終更新: 2026-08-25（Must M1-M5 の実装完了。決定事項 D1-D10 を §7 に記録）

## 1. 目的

上田将生が、ブラウザ上で形状パラメータと初期条件を対話的に変えながら、5種類のビリヤード（矩形・楕円・スタジアム・シナイ・卵型）の粒子軌道とポアンカレ断面を同時に見比べられるようにする。

既存の Python 実装（`class/` + `main/`）は、1回の実行に1組のパラメータしか渡せず、値を変えるたびにスクリプトを編集して再実行する必要がある。そのため「W をこの範囲で動かすとカオス化がどこで始まるか」といった探索が遅い。この HTML はその探索を高速化するためのものであり、論文用の図の生成は引き続き Python が担う。

## 2. 利用者と利用シーン

- **利用者**: 上田将生（本人のみ）
- **使う場面**: 形状パラメータ（W, H, D, W_r, W_l）や初期条件（位置・速度）を振って、軌道の見た目とポアンカレ断面の構造がどう変わるかを探索するとき。目星がついたパラメータを Python 側に持っていき、論文用の図を生成する
- **使う頻度**: 研究を進めている期間中に随時。1回のセッションで数十回パラメータを変える想定

## 3. スコープ内の機能

### Must（これが無ければ成立しない）

- [x] **M1. 形状の選択と形状パラメータの変更** — 矩形 / 楕円 / スタジアム / シナイ / 卵型 の5形状を切り替えられ、その形状が必要とするパラメータだけを入力できる。切り替えた結果、いま入力されている初期位置が新しい領域の外になった場合は、領域内の既定位置へ自動的に戻す
- [x] **M2. 初期条件の入力と再計算** — 初期位置 (x, y)、初速度 (vx, vy)、衝突回数 N を入力できる。**形状パラメータと初期位置・初速度は変更即時に再計算し、衝突回数の変更のみ「計算」ボタンで確定する**
- [x] **M3. 軌道図の描画** — 境界線・衝突点・軌道の線分を描画する。1衝突ずつ進むアニメーション再生と、N回分を一度に描く一括表示を切り替えられる。衝突番号スライダーで任意の衝突まで進める
- [x] **M4. ポアンカレ断面の描画** — 横軸に弧長 s（楕円・卵型は角度 θ）、縦軸に sinφ を取った散布図を描画する。直線部と曲線部の境界を示す破線を引く。軌道図はアスペクト比 1:1 を保ち、断面は横軸を枠幅いっぱいに引き伸ばす
- [x] **M5. 軌道図とポアンカレ断面の並置と相互ハイライト** — 2つの図を同一画面に並べ、**ポアンカレ断面の点を指すと軌道図の対応する衝突が強調される**（一方向）

### Should（あると価値が上がる）

- [ ] **S1. 多初期値の重ね描き** — 境界上に N 個の初期条件を自動生成し、色分けしてポアンカレ断面に重ねる（`main/create_setting.py` の `*_create_setting` 相当）。表示中は M5 の相互ハイライトを無効にする
- [ ] **S2. 占有領域の塗り分け** — ポアンカレ断面を divide × divide のセルに分け、各セルの通過回数を濃淡で塗る（`paint_occupany_area` 相当）
- [ ] **S3. シャノンエントロピー** — 衝突回数を増やしながら S を計算し、横軸 log2(N)・縦軸 S でプロットする。理論上限を水平線で示す（`shannon_entropy` 相当）
- [ ] **S4. 図の PNG 書き出し** — 表示中の軌道図・ポアンカレ断面をそれぞれ PNG として保存できる（ローカルで開いた場合のみ。未決事項 3 を参照）
- [ ] **S5. パラメータの URL 保存** — 現在のパラメータが URL ハッシュに反映され、その URL を開き直すと同じ図が再現される

### Could（余裕があれば）

- [ ] **C1. 卵型・楕円の焦点表示** — 境界上に焦点を点で示す（`setting.py: egg_set` 相当）
- [ ] **C2. ポアンカレ横軸の座標系切替** — 弧長 s と角度 θ を切り替えられる
- [ ] **C3. 複数粒子の同時表示** — 初期条件をわずかに変えた粒子を複数本同時に走らせ、軌道の分離を見る

## 4. 非スコープ（今回はやらない）

- **ダークモード非対応**。配色はライト固定。OS のカラースキームには追従しない
- **モバイル・タブレット非対応**。デスクトップ幅のみを対象とする。狭い画面でのレイアウト崩れは許容する
- **相互ハイライトの逆方向（軌道図 → ポアンカレ断面）のホバーは実装しない**。軌道図の衝突点は境界上に密に重なるためカーソルで特定できない。衝突番号スライダー（M3）で代替する
- **重ね描き（S1）表示中は相互ハイライト（M5）を無効にする**。100 本の軌道が重なった状態でのハイライトは両立させない
- **サーバ・DB・ログイン・アカウントを持たない**。計算結果はリロードで消える（S5 の URL 保存を除く）
- **Python 側の計算結果（JSON / CSV）を読み込む機能は持たない**。すべてブラウザ内で計算する
- **既存 Python コードの置き換えではない**。`class/` と `main/` はそのまま残し、論文用の図生成は Python が担い続ける。HTML はパラメータ探索用
- **ビルドツールを使わない**。npm / webpack / TypeScript / バンドラ / パッケージマネージャを導入しない
- **外部ライブラリ・CDN に依存しない**。ネット接続なしで動くこと。matplotlib 相当の描画は Canvas 2D で自前実装する
- **任意形状・多角形・3次元・磁場つきビリヤードは対象外**。上記5形状のみ
- **Web Worker / WebGL による高速化は対象外**。重い設定は衝突回数の上限で防ぐ

## 5. 受け入れ基準

1. 形状セレクタで「スタジアム」を選ぶと W と H の入力欄だけが現れ、「シナイ」を選ぶと W・H・D の3つ、「卵型」を選ぶと W_r・W_l・H の3つが現れる。その形状に無関係なパラメータ欄は表示されない（M1）
2. スタジアムで W = 0 を入力すると、境界が半径 H/2 の真円として描かれ、ポアンカレ断面の点が sinφ 一定の水平線上に乗る（M1）
3. 卵型で W_r と W_l に同じ値を入力すると、境界が左右対称の楕円として描かれる（M1）
4. 形状または形状パラメータを変更した結果、いま入力されている初期位置が新しい領域の外になった場合、初期位置が領域内の既定位置へ自動的に置き換わり、その旨が1行表示される（M1）
5. ページを開いた直後は、スタジアム W = H = 5.0、初期位置 (0.5, 0.0)、初速度 (0.02/√29, 0.05/√29)、衝突回数 2000 で計算済みの状態になっており、軌道図とポアンカレ断面の両方が表示されている（M2）
6. 形状パラメータ（W, H, D, W_r, W_l）と初期位置・初速度を変更すると、「計算」を押さずに両方の図が再描画される。ただし数値入力欄にフォーカスがある間は再計算しない（M2）
7. 衝突回数を変更すると両方の図が「未計算」表示に切り替わり、「計算」を押すまで古い図が残らない（M2）
8. 初期位置が外壁の外側にある場合、またはシナイで中央の障害物の内側にある場合、計算を実行せず、原因となった入力欄の直下にエラーが表示され、その入力欄の枠が強調され、「計算」ボタンが押せない状態になる（M2）
9. 衝突回数に上限（既定 20000）を超える値を入力すると、上限まで丸めた旨が入力欄の直下に表示され、ブラウザが応答不能にならない（M2）
10. 「再生」を押すと衝突点が1つずつ増えながら軌道が描かれ、「一時停止」で止まり、再度押すと続きから再開する（M3）
11. 「一括表示」に切り替えると、アニメーションを待たずに指定した衝突回数までの軌道が一度に描かれる（M3）
12. 衝突番号スライダーを動かすと、軌道図とポアンカレ断面の両方がその衝突番号までの表示に切り替わる（M3）
13. 5形状すべてについて、`tools/dump_section.py` が Python 側から書き出した既定ケースの参照値と、HTML 側が計算した `x, y, s（または θ）, sinφ` の各成分の差が 1e-6 未満で一致する。`simulation.html` の「検算」ボタン、または `node tools/check_html.js` で確認できる（M2, M4）
14. ポアンカレ断面の横軸範囲が、スタジアムでは [-(W + Hπ/2), W + Hπ/2]、矩形では [-(W + H), W + H]、シナイでは [0, 2(W + H + πD/2)]、楕円・卵型では [-π, π] になる（M4）
15. スタジアムと矩形では、直線部と曲線部の境界にあたる横軸位置に赤い破線が4本引かれる（M4）
16. 軌道図はパネルの形にかかわらずアスペクト比 1:1 を保ち、余りは左右または上下の余白になる。ポアンカレ断面は横軸を枠幅いっぱいに引き伸ばし、縦の高さは横軸範囲に依存しない（M4）
17. ポアンカレ断面上の点にカーソルを合わせると、軌道図上の対応する衝突点が強調され、それが何回目の衝突かが数値で表示される（M5）
18. パラメータを1つ変更すると、軌道図とポアンカレ断面の両方が新しいパラメータで再描画され、片方だけ古い状態が残ることがない（M5）
19. 重ね描き（S1）を ON にすると相互ハイライトが働かなくなり、ポアンカレ断面のみが表示される（S1）
20. ネットワークを切断した状態で HTML ファイルを開いても、上記1〜19がすべて同じように動作する

## 7. 決定事項（実装で確定したもの）

実装中に決めた内容。**削除ではなく理由ごと残す**。ここを変えるときは `docs/contracts.md` と `simulation.html` の両方を直すこと。

- **D1. 法線 n は全5形状で領域の内側を向く。**
  理由: スタジアムは直線部が内向き・円弧部が外向きで、断面の sinφ が接続点 s = ±W/2 で符号反転していた。楕円・卵型は勾配（外向き）のままで、内向きに揃っているシナイ・矩形と規約が逆だった。形状をまたいで断面を比較できないので統一する。
  影響: 反射計算 `v − 2(v·n̂)n̂` は n の符号に不変で、IEEE754 の符号反転は厳密なため、**軌道はビット単位でも変わらない**。変わるのは断面の sinφ の符号だけ。Python 側（`class/stadium_func.py`, `class/egg_func.py`）も同じ規約に揃えた。`tests/test_invariants.py` の検査 [4] がこの規約を固定している。

- **D2. ポアンカレ断面に載せるのは衝突点 1..N のみ。**
  理由: `poincare()` が `range(bound_num)` を使っていたため、境界上にない初期位置が1点混ざり、代わりに N 回目の衝突が捨てられていた。既定値 (0.5, 0.0) は内点なので、スタジアムでは意味のない `s = W + Hπ/2 − 0.5` が1点だけ出ていた。
  影響: Python 側の `poincare()` は `range(1, bound_num + 1)` に修正済み。`tests/test_invariants.py` にリグレッションガードあり。⚠️ `create_occupany_area()` には同じ off-by-one が残っている（S2・S3 の範囲。未決事項2）。

- **D3. 弧長 s の原点は形状ごとに既存のまま。**
  スタジアム・矩形は中央原点（負値あり）、シナイは右上角から 0 始まり。理由: Python が出す既存の図と横軸を直接見比べたいため。全形状 0 始まりに揃えると過去の図と対応が取れなくなる。

- **D4. 楕円・卵型の横軸は角度 θ = atan2(y, x) のまま。**
  理由: 弧長を出すには楕円積分が要る。C2（座標系切替）は Could のまま残す。
  ⚠️ この θ は弧長に比例しないので、断面上の点の密度はスタジアム・シナイの断面と直接は比較できない。

- **D5. 角（頂点にちょうど当たる）に来たら来た道を戻る（`v → −v`）。**
  理由: 角では2辺の法線が同時に効いて反射が一意に定まらない measure-zero の場合。矩形は `[0, 0]` を返して `0/0` で NaN になり、以降の軌道が黙って壊れていた。シナイの既存挙動（逆行）に揃えた。

- **D6. 相互ハイライトは「断面 → 軌道図」の一方向のみ。**
  理由: 軌道図の衝突点は境界上に密に重なり、カーソルで1点を指せない。逆向きは衝突番号スライダーで代替する（非スコープに明記済み）。

- **D7. 再計算の引き金を入力の種類で分ける。**
  形状パラメータのスライダーは `input`（ドラッグ中も即時）、数値欄は `change`（blur / Enter で確定）、衝突回数だけは「計算」ボタン。
  理由: 全部即時だと 20000 回の再計算が入力1文字ごとに走って固まる。全部ボタン待ちだと W を振って構造変化を追うという本来の用途が死ぬ。

- **D8. 境界上ちょうどの初期位置は領域外として扱う。**（受け入れ基準8の境界条件）

- **D9. 断面をホバーしても再生は止めない。** スライダーを掴んだときだけ止める（取り合いになるため）。

- **D10. 衝突回数の上限は 20000 のまま。**
  実測: スタジアム W=H=5 で 20000 衝突の計算が **47 ms**、ヒットテストは索引ありで 1 回 **0.017 ms**（全走査 0.729 ms の 44 倍速）。要件の「5 秒以内」に対して十分余裕があるため下げる必要はない。むしろ上げる余地がある。

## 8. 未決事項

1. **楕円は卵型カーネル（`W_r = W_l`）に統一し、`func/ellipse/` の Newton 法版は使っていない。** 両者が同じ値を返すかは未確認。`func/ellipse/` を消すか残すかも未決。
2. **`create_occupany_area()` に D2 と同じ off-by-one が残っている。** また `Stadium.paint_occupany_area` は未定義グローバルを参照していて `NameError`。S2・S3（占有領域・エントロピー）に着手するときにまとめて直す。TODO コメントは入れてある。
3. **S4 の PNG 書き出しは開き方によって動かない。** ローカルの `file://` では `<a download>` が動くが、sandbox 付きの環境ではページ自身が開始したダウンロードがブロックされる。その場合は「右クリック → 画像を保存」で代替する。
4. **実機での見た目が未確認。** 開発中は Chrome の preview ペインが `visibilityState: "hidden"` でビューポート 0×0 だったため、描画の検証はすべて JS から幅を与えて行った。`requestAnimationFrame` も発火しないため、アニメーションが実際に滑らかに見えるかは目視していない。
5. **キーボード操作（Tab 順序・Enter での確定）が未確認。**
